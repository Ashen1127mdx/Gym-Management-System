================================================================================
                             1. Project Description
================================================================================

1.1 Introduction
FitZone is a web-based gym management application developed to provide fitness 
centers with an automated, secure, and efficient platform for organizing daily 
gym operations, managing member plans, processing attendance check-ins, and 
tracking payments, while enabling members to track their plans and sessions. 
The system aims to replace traditional, manual gym record-keeping and simplify 
membership interactions through an organized, clean, and user-friendly interface.

The system supports three main user roles: Members, Trainers, and Admins. 
Members can manage their profiles, review check-in history, submit membership 
plan change requests, and check their workout routines. Trainers are provided 
with roster management tools, workout schedule creators, and coaching 
attendance trackers. Admins oversee all plans, approve or reject change requests, 
view financial reports, and manage trainer profiles.

The scope of FitZone covers the essential operations of a modern gym, including 
user authentication, member dashboard statistics, plan request handling, 
attendance verification, and session scheduling. The system is designed to 
ensure smooth interactions between administrators, training staff, and members.

Overall, FitZone is developed as a complete management solution for fitness gyms, 
providing a reliable platform that increases administrative efficiency, tracks 
revenue details, and improves member engagement.

1.2 Aims and Objectives

1.2.1 Aim
To design and develop a secure, responsive, and user-friendly web-based gym 
management system that provides members with a clean interface for billing and 
scheduling while enabling gym staff and administrators to manage fitness operations.

1.2.2 Objectives
1. To develop a member portal that allows users to register, track their plan 
   status, view session schedules, check attendance logs, and request plan upgrades.
2. To provide an administrative dashboard that enables gym managers to customize 
   plans, approve membership requests, log physical payments, and view real-time 
   revenue statistics.
3. To implement a secure role-based access control architecture using secure sessions 
   and clean prepared statements to guarantee reliable data operations.

================================================================================
                          2. System Functions/Features
================================================================================
FitZone is designed to provide clean, role-based workflows for gym managers, 
trainers, and members. The major functionalities are categorized below:

1. User Management
   - Registration and login systems for members and trainers.
   - Secure Admin login console.
   - Access control restricting API endpoints based on session roles.
   - Cross-tab profile updates using browser BroadcastChannel.

2. Membership Plan Management
   - Admin tools to add, edit, and delete plans.
   - Support for custom billing cycles (Daily, Weekly, Monthly, and custom days/weeks/months/years).
   - Plan request submission and tracking interface in the member portal.
   - On-the-fly expiration sweeps updating active subscriptions to "No Plan".

3. Attendance Logging
   - Front desk check-in interface for Admins to register member entry.
   - Coaching attendance logger for Trainers to record session attendance.
   - Dynamic check-in counters counting only admin-logged entries for front desk, 
     and trainer-logged entries for trainers.

4. Scheduling & Workout Routines
   - Session scheduler in the trainer's portal.
   - Workout builder to assign targets and sets to trainees.
   - Next session cards and routine trackers in the member dashboard.

5. Administration & Reporting
   - Payment logs recording transaction amounts and months on plan approvals.
   - Reports view featuring total actual revenue, estimated revenue, active 
     members counts, and request progress.

                    3. Use of Object-Oriented Programming (OOP)
================================================================================
The FitZone application applies Object-Oriented Programming (OOP) principles in 
the PHP backend to create a modular, maintainable, reusable, and secure structure. 
The backend is organized into config layers, controllers, and models.

3.1 Classes and Objects
Classes are used to group related functions into reusable modules. Instances 
(objects) of these classes are instantiated to execute business logic.
Main Classes Used:
1. Controllers: auth.php, members.php, trainers.php, plans.php, attendance.php, reports.php
2. Models: User.php, Member.php, Trainer.php, MembershipPlan.php, Attendance.php, Payment.php
3. Config: Database.php

Example:
class Member extends User {
    private $memberId;
    private $plan;
    private $planExpiresAt;
    
    public function __construct($db) {
        parent::__construct($db);
    }
}

3.2 Encapsulation
Encapsulation is achieved by making class properties protected or private and 
restricting direct modifications from outside. Accessible controls are exposed 
via methods (getters and setters) to keep the internal state safe.
Example:
class User {
    protected $id;
    protected $name;
    protected $email;
    protected $password;
    protected $phone;
    protected $role;
    protected $status;
}
The password is kept protected and is only processed through safe verify methods, 
preventing access from endpoint scripts.

3.3 Inheritance
Inheritance allows base structures to be reused by child classes, reducing code 
duplication.
Example:
Since Admins, Trainers, and Members share basic properties (id, name, email, phone, status), 
both Member and Trainer inherit from the User class:
class Member extends User {
    // Inherits name, email, phone, status, and db properties from User
}

3.4 Abstraction
Abstraction hides low-level database operations behind simple methods.
Example:
The Database class abstracts away details of PDO connections, query preparations, 
and transaction commits. Endpoints call simple methods without knowing how the SQL 
is run:
$member = new Member($db);
$member->update();

3.5 Polymorphism
Polymorphism allows methods to behave differently depending on the class object.
Example:
Both Member and Trainer override the base class methods to update their specific 
tables alongside the common `users` table:
// Member.php overrides save methods to handle members table fields
// Trainer.php overrides save methods to handle trainers table fields

3.6 Constructors and Dependency Initialization
Constructors initialize the required connection links when objects are created.
Example:
public function __construct($db) {
    $this->conn = $db;
}
